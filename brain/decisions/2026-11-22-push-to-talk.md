# Decision: push-to-talk replaces wake word + continuous SpeechRecognition
Date: 2026-11-22 | Status: superseded by [[2026-11-23-tap-to-talk]] (recording part only; streaming/TTS queue still active) | supersedes [[2026-11-22-voice-conversation]]
Context: browser SpeechRecognition (ar-SA) was unreliable for the name «دوبي» (see lessons/wake-word-asr-variants) and could not be verified headless (Edge returned empty/network errors).
Decision: hold 🎙 or Space (not while typing, not on other buttons) -> MediaRecorder -> ONE request to Edge Function `cat-voice`: Groq whisper-large-v3-turbo (language ar, verbose_json, no_speech filter) + library lookup in parallel, then the fast model (openai/gpt-oss-20b, Groq's replacement for the shut-down llama-3.1-8b) streamed back as SSE. Reply spoken per sentence by Groq Orpheus Arabic (noura) via `cat-tts`: first chunk after 3 words (or 9), up to 3 TTS requests in flight (prefetch), decoded + silence-trimmed, scheduled back-to-back in ONE Web Audio queue; a sentence slower than 2.5 s is spoken by the browser voice. Pressing again stops playback and the stream. Functions are pre-warmed (x-warm ping) on button down. Release -> first sound is printed in the console.
Why: removes the unverifiable browser recognizer; Whisper accuracy and one-hop latency are measurable.
Risks: cost per utterance (Whisper $0.04/h, Orpheus Arabic $40/1M chars, Groq docs 2026-11-22); mic stays warm 8 s after release (released after); target <2 s release->sound is UNVERIFIED on real services (stubbed e2e only), measure with scripts/test-voice.mjs and the browser console.
Revisit if: real latency > 2 s (consider sending WAV instead of webm, a faster model, or server-side TTS streaming).
